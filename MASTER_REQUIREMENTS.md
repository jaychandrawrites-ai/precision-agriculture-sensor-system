# Jupiter master requirements

This inventory carries forward AGENTS.md, PLANS.md, the original foundation,
and the Phase 1–6 research requirements. A later experiment or implementation
may extend a baseline. Preserve its compatibility and make the new method
explicit. Record status and verification in DEVELOPMENT_STATUS.md.

| ID | Requirement | Acceptance |
| --- | --- | --- |
| R01 | Repository and firmware continuity | Preserve main, archival branches, the consolidated foundation and the original Arduino files |
| R02 | Multi-location AI Trace | Durable surveys, repeated visits, independent segments, raw-first capture, interruption recovery, import and export |
| R03 | Receiver and calibration | Connect independently of a location, expose receipt/parse/GPS quality, retain explicit units and measured calibration |
| R04 | Hardware protocol | Verify native AquaMap from source or captures, support devices and restart boundaries, preserve unrecognized bytes |
| R05 | Physical features | Generate the six documented hourly features causally with explicit regularity checks and distinguish observations from simulations |
| R06 | Historical data | Verify station releases or explicit modern mappings, pin provenance and use chronological fit, selection, calibration and test periods |
| R07 | Numerical framework | Maintain manual NumPy/CuPy derivatives, reference solvers and finite-difference tests |
| R08 | Training and portability | Portable checkpoint schemas, exact CPU recovery and measured optional GPU/mixed precision behavior |
| R09 | Forecasting | Reproducible 18-input baseline, direct and sequence models, seasonal/harmonic methods and per-location abstention |
| R10 | Forecast uncertainty | Horizon/feature intervals, paired block evaluation, simultaneous scope and transfer limitations |
| R11 | Evolution | Resumable classical and amplitude-based search with candidate constraints, matched budgets, diversity and Pareto analysis |
| R12 | Spatial models | Measurements separated from forecasts, interpolation and variational baselines, conditioning, adaptive resolution and held-out checks |
| R13 | Spatial uncertainty | Analytical controls, multiple chains and diagnostics, distinct measurement/parameter/reconstruction effects |
| R14 | Spatiotemporal integration | Independent forecasts, common valid times, observed and forecast maps, propagated uncertainty and auditable provenance |
| R15 | Local application | Real persisted jobs and controls for survey, data, training, forecasts, mapping and research exports |
| R16 | Scientific evaluation | Independent data, actual results, honest negatives, reproducible metrics and figures |
| R17 | Project durability | Commit and push substantial milestones, retain tests, record constraints and next steps after interruptions |

No survey software may synthesize historical hours or treat visits separated by
unobserved time as one continuous record. Field data and exact positions
belong in local workspaces. Prior Tucson, Yuma and Maricopa results are
exploratory context for methods chosen after inspecting them.

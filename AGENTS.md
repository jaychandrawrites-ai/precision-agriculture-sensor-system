# Jupiter development instructions

Implement a functional, reproducible precision agriculture research platform. Read PLANS.md before making changes. Preserve existing Arduino firmware and work on the development branch or a task branch based on it.

- Inspect existing source before editing. Reuse working implementation rather than duplicate it.
- Use explicit manual backpropagation in the NumPy/CuPy framework.
- Implement complete usable modules, not empty placeholders. Do not pad to reach a line count.
- Prioritize an integrated runnable pipeline over optional extensions.
- Run relevant tests, report actual results, and record unfinished work.
- Never invent datasets, calibration measurements, citations, or experimental results.
- No private medical data, credentials, or precise personal locations in this public repository.
- Do not force push or delete existing firmware.
- Record progress in BUILD_LOG.md, including blockers and commands.
- Clearly distinguish classical quantum-inspired algorithms from quantum computing.
